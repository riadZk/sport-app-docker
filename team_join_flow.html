🏟️ Team Join Request - API Flow

Complete guide to test the Player ↔ Team join system with cURL commands

📋 Database Schema

table: team_join_requests

Column Type Description
id bigint (PK) Auto-increment
team_id foreignId → teams.id
player_id foreignId → player_stats.id (NOT users.id!)
requested_by enum player or team
status enum pending approved rejected cancelled
created_at timestamp
updated_at timestamp
⚠️ Important: player_id references player_stats.id, NOT users.id.
A user must have a PlayerStat for the team's sport_category_id before they can join.

🔄 Flow 1: Player Requests to Join a Team

1
Player clicks "Join Team" → creates record with requested_by = 'player', status = 'pending'
2
Team Owner sees the request in the list
3
Team Owner responds: approved or rejected
4
If approved → TeamMember is automatically created! ✅

Step 1 — Player sends join request

📌 Player must have a PlayerStat for the same sport_category_id as the team
# Player (token: PLAYER_TOKEN) requests to join team ID 5
curl -X POST http://localhost:8000/api/teams/5/join \
  -H "Authorization: Bearer PLAYER_TOKEN" \
  -H "Accept: application/json"

Step 2 — Team Owner lists join requests

# Team Owner sees all pending requests/invitations for team 5
curl -X GET http://localhost:8000/api/teams/5/join-requests \
  -H "Authorization: Bearer OWNER_TOKEN" \
  -H "Accept: application/json"

Step 3 — Team Owner approves (or rejects)

# Team Owner approves join request ID 1
curl -X PUT http://localhost:8000/api/teams/5/join-requests/1/respond \
  -H "Authorization: Bearer OWNER_TOKEN" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"status": "approved"}'

# Or reject it:
curl -X PUT http://localhost:8000/api/teams/5/join-requests/1/respond \
  -H "Authorization: Bearer OWNER_TOKEN" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"status": "rejected"}'

🔄 Flow 2: Team Invites a Player

1
Team Owner sends invite → creates record with requested_by = 'team', status = 'pending'
2
Player sees the invitation in "My Join Requests"
3
Player responds: approved or rejected
4
If approved → TeamMember is automatically created! ✅

Step 1 — Team Owner invites a player

📌 player_id here is the player_stats.id, NOT the user ID!
# Team Owner invites player_stat ID 3 to team 5
curl -X POST http://localhost:8000/api/teams/5/invite \
  -H "Authorization: Bearer OWNER_TOKEN" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"player_id": 3}'

Step 2 — Player checks their invitations

# Player sees all their requests & invitations
curl -X GET http://localhost:8000/api/my-join-requests \
  -H "Authorization: Bearer PLAYER_TOKEN" \
  -H "Accept: application/json"

Step 3 — Player accepts (or rejects) the invitation

# Player accepts invitation (join request ID 2)
curl -X PUT http://localhost:8000/api/teams/5/join-requests/2/respond \
  -H "Authorization: Bearer PLAYER_TOKEN" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"status": "approved"}'

❌ Cancel a Request / Invitation

📌 Only the requester can cancel:

• If player requested → Player cancels

• If team invited → Team Owner cancels

# Cancel a pending join request (ID 1) — by the requester
curl -X PUT http://localhost:8000/api/teams/5/join-requests/1/cancel \
  -H "Authorization: Bearer TOKEN" \
  -H "Accept: application/json"

📊 All Endpoints Summary

Method Endpoint Who Description
POST /api/teams/{team}/join Player Player requests to join (no body needed)
POST /api/teams/{team}/invite Team Owner Owner invites player (body: player_id = player_stats.id)
GET /api/teams/{team}/join-requests Team Owner List all requests/invitations for the team
PUT /api/teams/{team}/join-requests/{id}/respond Other side Approve or reject (body: status)
PUT /api/teams/{team}/join-requests/{id}/cancel Requester Cancel a pending request
GET /api/my-join-requests Player See all your requests & invitations

🧪 Prerequisites for Testing

1. Create a Player Stat first (required before joining)

curl -X POST http://localhost:8000/api/players \
  -H "Authorization: Bearer PLAYER_TOKEN" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{
    "sport_category_id": 1,
    "primary_position": "Forward",
    "prefered_foot": "right"
  }'

2. Create a Team (as Team Owner)

curl -X POST http://localhost:8000/api/teams \
  -H "Authorization: Bearer OWNER_TOKEN" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "FC Test",
    "sport_category_id": 1
  }'

✅ What Happens on Approve?

When status is set to approved, a TeamMember record is automatically created:

Field Value
player_id From join request → player_stats.id
team_id The team
context 'club'
start_date Current date (now)
role 'player'

📌 Uses firstOrCreate — won't duplicate if member already exists.
